# Isolated Creator Inspection

Independent workers on the existing Vercel Pro team: Staging `feedx-creator-inspection-staging` / `prj_iBtNFmS6Jqso4P8S5GkM5ZO2THKJ`; Production `feedx-creator-inspection` / `prj_2nhqG8hHncVLi6LLHK6lY8HVMWwY`. No dedicated server, additional seat or fixed subscription. Usage remains team-metered.

The canonical extractor source stays in `server/creatorExtraction`; `node scripts/packageCreatorInspection.mjs --manifest` packages an independent, immutable deployment from that source and this directory's locked dependencies. The generated runtime is not a second maintained copy. Deploy this artifact to the worker project only, recording source SHA and artifact digest. No Git integration is attached: ordinary FeedX commits do not redeploy Chromium. Retain current worker plus at least three accepted compatible rollback versions. Do not delete versions without separate approval.

The main API retains Admin/Brand authorization, quotas/leases, official Instagram calls, duplicate detection and post-read checks. Only anonymous public metadata extraction crosses the workload boundary; no Admin JWT, social credential or database credential goes to the worker. The worker verifies signed Vercel OIDC identity for the exact environment-bound gateway project/team/environment and rejects arbitrary options, unsupported URLs, oversized input and invalid deadlines before extraction. Existing DNS pinning, private-IP blocking, resource allowlists, GET-only transport, byte limits, deadline guards, disabled WebGL and cleanup remain authoritative. Paid extraction is always disabled.

Gateway calls use the fixed HTTPS endpoint, no redirects/retries, a deadline-bound abort and a bounded, identity-checked metadata response. Main `npm run build` traces every current API route and rejects browser dependencies. Chromium remains a main **development-only** dependency for existing isolated extractor regression tests, not a main runtime dependency. Worker production dependencies own Chromium. Vercel Resources and dependency traces must also be checked after delivery.

Worker and gateway each emit sanitized `feedx.function` start/finish events. Use their separate project/route dimensions for invocations, platform Active CPU, errors/timeouts and memory. Wall milliseconds are not CPU. Do not log URLs, tokens, raw HTML or user/business data.

`server/creatorExtraction/bindings.mjs` owns exact gateway/worker project IDs and endpoint pairs. Each worker sets its matching `CREATOR_INSPECTION_ENVIRONMENT` and `CREATOR_INSPECTION_PROJECT_ID`. The gateway sets its matching `CREATOR_INSPECTION_ENDPOINT`. Both use Vercel production targets; business environment follows project identity, never that target label. Deployment Protection trusts only the corresponding gateway, and independent application JWT verification repeats that boundary. No static bypass, Admin or database credential is installed on either worker.

For Production rollback, preserve the previous accepted main deployment at `8210a6867d0bf5c54bd6bfb8d539cf593486bc6f` and its aliases; revert/promote only under the governed release policy. Keep the new worker compatible while rolling back. Never point Production to the Staging worker, automatically fail over, or silently run a second Chromium request.
