# FeedX macOS Print Bridge · Staging
## Guided installer

1. In FeedX Staging, open **Factory Settings → Label Management → Printers → Set Up Printer** and download the Apple silicon package. Install it on the computer connected to the printer, then open **FeedX Print Bridge Staging** in Applications. The package bundles supported Python 3.13, TLS certificates, and the precompiled Bluetooth helper. The package targets macOS 12+ on Apple silicon.
2. Choose **Connect / Configure**. Sign in with a FeedX Staging account that can complete Production. The setup app obtains the public client configuration from the canonical Staging host and creates a separate FeedX Auth session in the user’s Keychain. Existing bridges remain tied to their original operator. Choose an installed CUPS queue or the Bluetooth-paired D520. Enter stock width and length, and the measured Bluetooth gap. Use portrait; CUPS queue media and gap are configured in the driver, and the D520 uses its established feed direction.
3. Choose **Connection Check** to query the printer without sending a label. Use **Test / Review Calibration** only when authorized to print. Approve one label, inspect it, then separately approve the three-label confirmation for D520 Bluetooth. Check count, frame, dimensions, and orientation before recording the outcome. Local unresolved calibration prevents claims. A completed Bluetooth write without an ACK still requires physical inspection.
4. Back in FeedX, verify bridge Online, printer Available, calibration Passed, and zero Unresolved Jobs. On later sign-ins the LaunchAgent starts in the same macOS user session. Reopen the app and choose **Reconnect** to reuse the saved printer and calibration. **Connection Check**, **Reauthorize** and calibration review remain available separately. Session-store failures and temporary network failures back off while preserving unresolved print evidence. Expired sign-in directs the operator to Reauthorize. Upgrade by installing the new package over the existing app. The installer payload leaves the user’s configuration, Keychain identity, calibration ledger and recovery journal in place.

This Staging package is ad hoc signed at the application level. Organization-approved distribution, Developer ID signing and notarization are prerequisites for commercial rollout. Use the legacy instructions below only for the source/script distribution.

## Legacy script setup

Requires macOS, Python 3.9 or newer, and an authorized FeedX Staging operator with the existing Production Complete permission. Extract this package into a folder that the operator can keep. Open Terminal in that folder. The bridge runs as the signed-in macOS user and talks only to FeedX Staging over outbound HTTPS. The login password is used once, the session is stored in the login Keychain, and the private local journal keeps its device and claim IDs across restarts.

## Configure and run

1. Run `./Start-Bridge.command printers`. It lists installed CUPS queues and reports the D520 Bluetooth device after setup. Run `./Start-Bridge.command bluetooth-probe` to verify a paired D520 without printing.
2. **CUPS:** Connect the printer with the vendor-supported driver (USB is the documented macOS driver path). Confirm the exact queue appears in `lpstat -p -a` and its driver supports custom PageSize. Set the driver for 203 DPI, 80 × 90 mm stock, matching gap, portrait orientation, and actual size. Run `./Start-Bridge.command setup --queue 'Exact_Queue_Name'`. The bridge submits a monochrome 203 DPI PDF with an exact-size page and requests no scaling. Confirm that the driver honors those settings before printing operational labels.
3. **D520 Bluetooth Classic:** Install Apple Command Line Tools if needed. Quit Labelife, power on the D520, and pair it in macOS Bluetooth settings. Run `./Start-Bridge.command bluetooth-probe` to query its bitmap mode without printing. After inspecting and explicitly acknowledging any previous calibration, run `./Start-Bridge.command setup --bluetooth --gap 2`, replacing 2 with the measured gap in millimeters. The bridge selects the standard SPP service by its SDP service class and requires the printer to report bitmap mode 4. On the tested D520, firmware V1.1.3 reports mode 4 over RFCOMM channel 1. Physical output still requires calibration. The D520 transport defaults to inverted wire bits and TSPL direction 1 for this printer’s feed orientation. If the printed polarity is reversed on another unit, inspect the attempt before configuring `--no-invert` and recalibrating.
4. Enter the **Staging publishable/anon key** and sign in with your FeedX Staging operator. Setup registers a persistent local device ID. Run `./Start-Bridge.command start` or double-click Start-Bridge.command after setup. Keep the Terminal window open. Ctrl-C stops the bridge. Run setup again as the same operator if the session needs renewal or if you change the queue. Follow your organization’s software policy.
5. In **Factory Settings → Label Management → Printers**, check that the bridge appears with its configured printer and connection, and becomes Ready. Then use **Print Labels** from a completed Job Order for operational work.

## Test Print and physical acceptance

Stop the bridge first. Load the correct 80 × 90 mm gap stock and calibrate its sensor using the printer’s instructions. Run `./Start-Bridge.command test-print 1`. This submits a local calibration label, independent of any Job Order or packaged-unit allowance. The asymmetric mark belongs in the upper left. The frame sits about 4 mm from each edge and measures about 72 × 82 mm. Measure both axes and check orientation, clipping, polarity, and gap feed.

After physically checking the printer and clearing any held CUPS job, run `./Start-Bridge.command acknowledge-test`. Enter `PASSED` only if the count, orientation, dimensions, and feed are correct. Enter `INSPECTED` to clear the attempt without passing it. Run `./Start-Bridge.command test-print 3` after the single label passes. Verify exactly three complete, aligned labels without skips and acknowledge again. Bluetooth claims are paused until both checks pass. Test a representative authorized Staging label for text, logo, barcode and QR scan readability, and check reconnect behavior on sacrificial stock before operational use.

The local calibration marker pauses claims until reviewed. Sent means macOS accepted the submission. Even a D520 submission acknowledgment or CUPS job receipt does not prove paper output. A failed write, negative acknowledgment or completed write with no observed print acknowledgment is Unknown. These cases are logged separately and never retried automatically. Inspect the printer for partial output and inspect/cancel any held CUPS job before acknowledging. Never repeat a test blindly.

For an Unknown operational job, open **Job Order → Print Labels → History**. An authorized verifier can select **Confirm Printed**, check the full requested count, then confirm it inline. For missing, partial or unusable output, select **Report Issue**, enter the usable count and the reason, and acknowledge that held output was cleared. The next queued job can proceed once the hold is resolved. Stop the bridge and inspect the physical printer and any held CUPS job before resolving uncertain output or requesting an authorized reprint. A restart converts an interrupted submission to Unknown and retries only the report. A lost claim response retries the same claim ID. Do not delete the journal. It lives under `~/Library/Application Support/FeedX Print Bridge Staging`.

## D520 Bluetooth completion evidence

- On the Staging D520, firmware V1.1.3 and bitmap mode 4 were read over RFCOMM channel 1. Two idle read-only sessions returned `SSSGETPAPER:YES` and `SSSGETCAP:CLOSE`. In both sessions the `SSSGETPRINTING\r\n` write completed and the printer returned 26 bytes within an eight-second receive window. The raw capture in the second session decoded to `Cmd error:SSSGETPRINTING\r\n`. The sessions returned neither framed ACK nor NAK. Paper and cover replies describe sensor state and carry no job or copy count.
- Static inspection of Labelife for macOS 3.3.01 found RFCOMM `writeSync` in the MTU-sized send loop and a separate receive callback. Its command strings include `SSSGETPRINTING`. [Independent Labelife protocol notes](https://github.com/thermal-label/labelife/blob/main/docs/protocol/tspl.md) describe optional per-payload ACK framing on some Classic Bluetooth models and a separate printing-status query. They list D520BT as untested. No public vendor contract was found that ties either response to completed output on this firmware.
- The earlier one-copy calibration, one-copy S9 sample, and three-copy S9 sample all printed as physically verified by the operator. The bridge completed its RFCOMM writes and recorded helper exit 8 with no recognized ACK or NAK for each submission. An RFCOMM write completion records transport progress. A positive submission ACK, where available, can support Sent. Confirmed requires physical-output evidence for the job and full copy count. No automatic completion signal was established for this unit, and uncertain submissions require operator review with no automatic resend.
