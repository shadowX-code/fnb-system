# FeedX AutoCount Connector for Windows

Download the Staging installer from **Finance → Data Sources → Connect provider → AutoCount Desktop**. Install it under the Windows account that will run sync. Detect the local SQL instance and authorize the books you intend to connect. Use AED_TEST for the Staging acceptance run. The installer saves authorized books locally, so installation and authorization can happen before pairing.

Generate a pairing code in Windows. In FeedX, enter it under **Connect provider → AutoCount Desktop**, review the computer name, then confirm. Codes expire after 15 minutes, work once, and can be regenerated in Windows. Use **Test Connection** in Windows to send authorized book metadata immediately, or wait for the next background check. Newly authorized books use the same pairing.

In FeedX, select the active Legal Entity for the authorized book and click **Connect book**. The Connector picks up new bindings and retry requests in its five-minute check. It runs a daily sync while the installing Windows user is signed in. The date selected on Windows determines the first posting date to sync. **Test Connection** checks FeedX pairing and verifies SQL reader permissions, book identity, and authenticated FeedX check-in for approved, bound books. It sends no accounting rows. **Sync Now** starts a manual sync for those books. Diagnostics shows test results, extracted and accepted counts, pending uploads, and errors. Use **Copy diagnostics** to share the result without sending the connector's local data files.

For office-PC acceptance, use this same installer and bind only AED_TEST. Run Test Connection and verify that both SQL and FeedX report Connected for AED_TEST. Run Sync Now and compare the connector’s counts and pending uploads with the accepted evidence in Finance. When testing a retry, use the same app and confirm that the queue drains after connectivity returns.

Generate a code on the new PC and enter it under **Replace computer** in Finance to keep the same device record. Re-authorize the same books on that computer. The connection and accepted history stay on the original Legal Entity. The replacement computer starts a fresh local checkpoint from its chosen posting date. The server recognizes repeated batches and keeps changes as new snapshots. If the original SQL database identity changed, review the historical binding before creating a new one.

The installer is per user. It launches Windows PowerShell 5.1 and WinForms internally. It requires 64-bit Windows, a local SQL Server instance, and SQL authentication enabled for the dedicated read-only user. Discovery does not open other databases. The SQL adapter does not require the AutoCount SDK. Keep native reporting status separate from SQL verification.

To rebuild, run `python3 installer/build.py <output.exe> <staging-publishable-key-file>` from the connector directory with NSIS installed. The file must contain only the Staging publishable API key. The binary is a Staging test build and is unsigned.
