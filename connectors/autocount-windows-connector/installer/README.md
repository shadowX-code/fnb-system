# FeedX AutoCount Connector for Windows

Download the Staging installer from **Finance → Data Sources → Connect provider → AutoCount Desktop**. Install it under the Windows account that will run sync. Detect the local SQL instance and authorize the books you intend to connect. Use AED_TEST for the Staging acceptance run. The installer saves authorized books locally, so installation and authorization can happen before pairing. If SQL reader verification fails, you can still pair the computer.

Generate a pairing code in Windows. In FeedX, enter it under **Connect provider → AutoCount Desktop**, review the computer name, then confirm. Codes expire after 15 minutes, work once, and can be regenerated in Windows. If you repeat setup on a paired computer, the connector confirms the active pairing with the saved device credential. Use **Test Connection** in Windows to send authorized book metadata immediately, or wait for the next background check. Newly authorized books use the same pairing. A selected book whose company identity was verified but whose reader failed appears as **Authorization Required**. Resolve the SQL reader issue and run **Test Connection** again. The connector reuses a pending reader from this installer on retry. For an unexpected object or schema permission, use **Copy diagnostics** after retrying authorization. It reports the first rejected object or schema, its effective permissions, the approved scope and relevant direct, public or inherited catalog entries when visible. Have the SQL administrator review these entries on the selected book before changing grants.

For the AED_TEST permission blocker, select **A2006 → AED_TEST** and click **Diagnose Permissions** under the Windows account that has both SQL administrator access and the saved reader. The connector checks the catalog type of `dbo.DeptChangeLog`, effective SELECT, scoped grants (including `public`), roles, and ownership. SQL Server can report bare object-level SELECT on catalog objects that cannot serve as a source of rows. The authorization check excludes only that result for recognized metadata types, including triggers, defaults, check and key constraints, rules, plan guides, statistics trees, table types, and SQL Server internal tables. It still checks other permissions on those objects, column-level SELECT, SELECT on readable or unknown objects, and inherited or broad access. Review the result in Diagnostics, or use **Copy diagnostics** to share it.

**Review & Repair** is available for a verified, isolated direct SELECT grant on that table to the saved, disabled pending reader. The confirmation shows the exact revoke. After approval, the connector checks the evidence again, verifies the revoke before committing and reruns normal book authorization with the saved credential. When evidence is ambiguous or access is inherited, SQL administrator review is required.

Updates preserve existing reader/device credentials, local queues and book configuration, and start the existing owned background task. A disabled task stays disabled; a password-backed task retains its stored Windows credential. The worker resolves the current database Profile/broker identity with saved restricted readers before publishing or syncing books. Historical identities are skipped without deleting their records, queues or bindings. If the current identity is unbound, explicitly connect that book to its Legal Entity in FeedX; do not move the historical binding or infer identity from a shared database/company name. Same-name books and source status show separate book references.

Select **Enable unattended sync** under the Windows account that installed the connector. Enter that account's Windows password to register the same five-minute task for signed-out operation. Windows Task Scheduler stores the password and the account needs batch logon rights. The connector uses the existing Windows-protected reader, pairing and queue. The task resumes periodic checks when Windows is running again. Five-minute checks run queued/requested/failed work and bounded seven-day GL catch-up; once caught up, the normal reference/history refresh is daily. No open Windows UI is needed for periodic work. Windows diagnostics show the task mode, last result, missed runs and the latest worker poll.

For `SQL_ERROR_4060`, download the [read-only AED_TEST database-open audit](https://fnb-system-staging.vercel.app/downloads/FeedX-AED_TEST-4060-Audit.ps1) to the office PC. Run it under the installing Windows account with local SQL administrator access. It reports database availability, saved-login state, user SID mapping, CONNECT, task identity and sanitized SQL error states. It uses existing credentials, does not repair access and does not upload accounting rows. The audit inventories saved book identities and active/pending reader presence. When local SQL administrator access is available, it matches the current Profile/broker fingerprint rather than assuming one record per database name. Ambiguous identities remain unresolved; task and database-state diagnostics still run. Share its JSON output before changing the reader.

For update acceptance, install over the existing Connector under the same Windows account, enable unattended sync with that account's Windows password if the task is still Interactive, and close the UI. Do not click Sync Now or Request Sync. After two scheduled runs, check Task Scheduler result `0`, the current book reference in Finance, fresh device check-ins, the next scheduled run, zero pending retries and accepted/reused receipts. Bounded GL catch-up may create new dated snapshots; repeated identical COA/Department/Project observations must reuse snapshots. Historical connection status and receipts remain separate. Windows diagnostics include worker startup failures and per-book stages, sanitized SQL error/state, credential-read failures and historical identity skips.

Generate a code on the new PC and enter it under **Replace computer** in Finance to keep the same device record. Re-authorize the same books on that computer. The connection and accepted history stay on the original Legal Entity. The replacement computer starts a fresh local checkpoint from its chosen posting date. The server recognizes repeated batches and keeps changes as new snapshots. On retry, the connector normalizes the legacy empty-object scope date on undated batches for transmission, retaining the original request ID and rows. The queue file is deleted only after the original request receives a matching acceptance receipt. If the original SQL database identity changed, review the historical binding before creating a new one.

The installer is per user. It launches Windows PowerShell 5.1 and WinForms internally. It requires 64-bit Windows, a local SQL Server instance, and SQL authentication enabled for the dedicated read-only user. Discovery does not open other databases. The SQL adapter does not require the AutoCount SDK. Keep native reporting status separate from SQL verification.

To rebuild, run `python3 installer/build.py <output.exe> <staging-publishable-key-file>` from the connector directory with NSIS installed. The file must contain only the Staging publishable API key. The binary is a Staging test build and is unsigned.
