# WhatsApp Embedded Signup and receive-only Coexistence pilot

## Delivered contract

Phase 2 builds on `71bec23b8`. Migration `20261021150315_marketing_whatsapp_embedded_signup.sql` adds private readiness evidence, one-Brand pilot authority, actor-bound single-use signup sessions, generation-bound onboarding steps and encrypted synchronization quarantine. No readiness record, pilot approval, credential or enabled environment flag is seeded by deployment.

Connections owns Connect, Retry Verification and Reconnect. The server and database validate Settings Configure, active Brand/member access, exact authorized business/WABA/phone and expected generation. Ordinary viewers receive safe state only. Official SDK v4/v5 completion is paired with the SDK authorization-code callback in either arrival order. Trusted origins are exact matches; the code remains in memory and is exchanged server-side once. SDK loading occurs only after authorized preparation; Continue calls `FB.login` synchronously from the user gesture. Cancellation, scope change and timeout remove listeners.

The Meta business token must be a valid SYSTEM_USER token for this app, grant both WhatsApp permissions and a granular management grant for the exact WABA. Provider reads verify WABA owner business, WABA phone membership, `is_on_biz_app=true`, `platform_type=CLOUD_API`, and the app's active exact webhook callback/fields. Unknown fields, incomplete pagination, mismatched assets and missing evidence fail closed. Existing FB user-token extension is not used. Existing AES-GCM storage/binding and previous-key support remain authoritative. A non-expiring business token receives a maximum 24-hour verification lease; Retry Verification renews that lease through provider reads. No automatic refresh or token rotation occurs.

Only the approved WABA webhook subscription and once-only contacts/history synchronization can be installed after durable server intent. Phone registration, deregistration, migrations, sends, template writes and app-setting writes are absent. A timeout, missing receipt or lost checkpoint leaves Action Required; no blind replay occurs. Subscription read-back can reconcile its existing intent. Contacts/history uncertainty requires provider/support evidence or an explicitly authorized offboarding/re-onboarding decision, never automatic offboarding.

Reconnect retains exact Brand/WABA/phone/mode, increments generation and resets receive verification and signed-inbound evidence. It retains previous synchronization receipts/progress so once-only APIs are not replayed. Exact phone uniqueness applies across tenants, including disconnected records. Replacement or ownership transfer remains unavailable. Concurrent callbacks bind only their captured generation.

Signed lifecycle and synchronization webhooks pass through the existing raw-body HMAC boundary. Account removal/offboarding closes receive authority; a reconnect event alone cannot reopen it. History/contact payloads are encrypted before durable acknowledgement, quarantined for 24 hours, and never promoted to live Inbox, CRM identity or consent. The existing Inbox worker purges expired quarantine/session records. Credential or Meta-subject erasure removes related quarantine. Historical message display/media imports are outside this receive-only pilot. Current messages and mobile outbound echoes retain the foundation's exact-ID deduplication and human ownership; signed current-generation inbound evidence is required before Connected. Unknown receipts remain reconciling. Sending, automatic/hybrid AI and campaigns remain disabled independently of connection state.
